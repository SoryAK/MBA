## Optional: Deferred Ideas

- **Ollama-style daemon auto-start** — user asked how Ollama handles the
  install-vs-start problem. Answer: Ollama's installer registers an OS service
  (systemd on Linux, Windows service, Ollama.app on macOS) so the daemon
  auto-starts and stays alive; the CLI is a thin client. MBA currently has no such
  registration — `npm install` gets the code, `npm run start:service` is the manual
  "wake it up." If ever wanted, the idiomatic move is a **systemd user unit**
  (`systemctl --user enable mba`), NOT an npm `postinstall` hook (wrong tool for a
  long-running daemon: runs during install, can't survive reboots, breaks in
  CI/sandboxed installs). Parked — not part of the locked bug-fix scope.
